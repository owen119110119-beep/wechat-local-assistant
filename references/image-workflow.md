# 图片整理与交付

连续收到课件、手写、白板或截图，先收集并自然询问是否还有图片；记住同条文字及后续文字/语音中的重点。用户明确发完再整合，不能按静默时间擅自结束，不要求固定口令。只问尚缺信息。明确的单图翻译、问答或编辑直接处理，不强迫课件流程。

默认按主题合并核心知识、去重，生成简洁中文PDF。实际查看图片和OCR，保留来源图序；公式、手写、数字或图表不清楚时说明具体缺项，不脑补。用户可以改顺序、删页、另开一批、补充重点或取消，也可以要求文字提取、翻译、图表说明、表格文件、图片比较、截图问答、复习题或其他成果；根据本次目标选择，不堆砌无关输出。

成果整理或编辑完成并回传后，先简短反馈结果，再用独立聊天气泡建议知识库分类，询问是否保存、选哪类，以及是否设置待办。分类按实际内容/用途和已有目录给一个具体推荐（普通或重点之一，加具体类别/用途），让用户接受或修改，不只罗列“普通还是重点”。普通与重点二选一，待办独立选择；这些问题不能写进PDF或图片。用户已明确的文字或语音意见直接执行，只问缺项，不二次确认、不要求编号或口令。已明确拒绝、普通聊天或仅补发旧文件，不反复询问。

Codex网关每轮提供`imageTask`：包含已收到的图片顺序、用途、真实本机路径和内部操作入口。通过给定程序维护批次、生成PDF与排队发送；生成PDF后查看返回的渲染预览再发送。此内部参数不能发给手机用户。编辑先看原图，使用宿主实际可用的图像编辑工具，成果另存到本轮输出目录后作为图片回传。工具不可用时说明具体限制，不假称修图成功，不擅自改用收费API或第三方。

WorkBuddy使用原生附件收发和工具，按同样的收图/结束/分析规则处理；接收文件路径与消息发送入口以宿主实际工具为准，不能套用Codex内部数据库工具。可调用部署目录`scripts/image_report.py --spec 内容JSON --output-dir 输出目录`导出中文PDF；依赖由`scripts/setup-content.py`安装到部署目录`.venv`。

PDF和图片直接回微信，不能只回复电脑路径。文件已生成、排队、接口发送成功与用户确认收到是不同结果，按实际情况表达。发送失败保留成果，可补发，不重新要求上传或盲目重跑编辑。原图保留；返回文件不代表知识库入库，只有用户明确要求保存并明确分类时才写入。保存成果文件时复制到知识库持久附件并在笔记关联，不只链接运行时缓存；待办放知识库根目录“待办事项”，保留已有内容，写入读回再报告。原有链接与群聊规则保持。
